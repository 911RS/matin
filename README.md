Matin picks your outfit each morning. You photograph your clothes once, the app cuts each piece out of its background, and every day it suggests an outfit from your closet based on the local weather and what you wore recently. You can swap a piece, shuffle the whole outfit, and mark it as worn. A daily push reminds you at the time you choose.

## Features

- **Photo to cut-out.** Background removal, dominant colour and labels run on the device (Vision on iOS, ML Kit on Android, MediaPipe on the web). Nothing is uploaded for processing; photos only leave the phone if you sign in to sync.
- **Weather-aware suggestions.** The outfit engine reads the forecast (MET Norway) and adds a coat when it is cold or skips the jacket when it is warm.
- **Variety.** It avoids pieces you wore recently and explains each pick in one short line.
- **Swap, shuffle, mark as worn.** Change one piece or the whole outfit, and see what you wore in the history calendar.
- **Tomorrow preview** and occasion chips, to plan ahead.
- **Works without an account.** Guest mode keeps everything on the phone. Signing in (Apple, Google or an email code) syncs the closet through Supabase and enables the morning push.
- **Offline first.** Reads are cached, so the app opens without a network.

## Tech stack

| Part | Built with |
|---|---|
| App | Expo SDK 57, expo-router, React Native New Architecture, TanStack Query |
| Outfit engine | Pure TypeScript package, no dependencies |
| Photo processing | Custom Expo native module (Swift / Kotlin), MediaPipe on the web |
| Backend | Supabase: Postgres with row level security, Storage, Edge Functions, cron |
| Tests | Vitest (engine, backend, SQL on PGlite), Jest (app) |


## Requirements

- Node 24 and pnpm 10 (`corepack enable`)
- For Android: Android SDK, an emulator or device, JDK 17
- For iOS: a Mac with Xcode (the iOS build has not been run yet, see `docs/release-checklist.md`)
- For the backend: the Supabase CLI

Install once from the repo root:

```
pnpm install
```

## Running the app

The app reads three build-time variables. Copy `apps/mobile/.env.example` to `apps/mobile/.env` and set what you need:

| Variable | Meaning |
|---|---|
| `EXPO_PUBLIC_DEMO` | `1` runs demo mode. It wins over everything else. |
| `EXPO_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key |

Modes:

- **Guest mode:** leave all three empty. The app starts on onboarding, everything is stored on the phone, no sign-in screen.
- **Demo mode:** `EXPO_PUBLIC_DEMO=1`. On first launch the app seeds 8 pieces, a Paris location and 5 days of worn history into a separate local store, and skips onboarding. Seeding runs once; relaunching does not add duplicates.
- **Supabase mode:** set the URL and anon key. The app starts on the sign-in screen, with a "continue without an account" option. Set up the project first with [docs/backend.md](docs/backend.md).

### Expo Go (quick look)

```
cd apps/mobile
npx expo start --go
```

Scan the QR code with Expo Go (iOS or Android). Everything runs except the native parts, which degrade instead of crashing: background removal is off, so a new piece is saved with its photo as is, and on Android the morning reminder is unavailable (Expo Go removed notifications there). Use a development build for the full app.

### Android development build

The full app (background removal, reminders) needs a development build.

```
cd apps/mobile
npx expo run:android                      # builds the dev client, installs it, starts Metro
EXPO_PUBLIC_DEMO=1 npx expo run:android   # same, in demo mode
```

After the first build, `npx expo start --dev-client` is enough while only JavaScript changes. Changes to `EXPO_PUBLIC_*` need a Metro restart (`npx expo start --dev-client --clear`).

A local release build (signed with the debug keystore, for testing only):

```
npx expo run:android --variant release
```

Release builds inline the `EXPO_PUBLIC_*` values when the JavaScript bundle is built. Put them in `apps/mobile/.env` rather than the shell: a running Gradle daemon keeps the environment it started with.

### iOS development build (EAS)

Needs an Apple Developer account (paid). `apps/mobile/eas.json` defines the `development`, `preview` and `production` profiles.

```
cd apps/mobile
npx eas login
npx eas device:create                                   # register the iPhone (open the link on the phone)
npx eas build --profile development --platform ios      # install from the link EAS prints
npx expo start --dev-client
```

The first EAS build also asks to run `eas init`, which adds the project ID to `app.json`.

`apps/mobile/android` and `apps/mobile/ios` are generated by `expo prebuild` and are not committed.

### Web (PWA)

The same app runs in the browser as an installable PWA. Guest mode is the default; sign-in (Google, email code) appears when the Supabase variables are set.

```
pnpm --filter @tenue/mobile build:web   # fetches the MediaPipe files, exports to apps/mobile/dist-web, writes the service worker
cd apps/mobile
npx serve dist-web -s -l 4173           # local preview at http://localhost:4173
```

To install it on an iPhone, open the site in Safari, tap Share, then Add to Home Screen. On Android, Chrome offers the install itself, and Settings shows an "Install the app" row.

Limits on the web: no push reminders (Settings says so), no Apple sign-in, and background removal needs a browser with WebAssembly. On iOS Safari, guest data in a tab that is not installed can be cleared after 7 days without a visit, so install the app or sign in. Hosting steps, caching and the Supabase redirect URL are in [docs/web.md](docs/web.md).
